# patches/

C that becomes bytes in MED9.1.1 flash. The pipeline, the placement policy and
the safety rules are in [`docs/06_patch_pipeline.md`](../docs/06_patch_pipeline.md);
this file is the map of the directory.

**Nothing here is ever flashed by a tool in this repository.** `make apply`
produces a file under `work/`; a human writes it with KESSv2 following
`docs/04_re_guidelines.md` §6.

```
patches/
  common/                the framework every patch links with
    patch.ld             linker script: .text/.rodata in flash, .bss in the
                         patch RAM block, ASSERTs for .data / small data /
                         RAM size / free-flash bounds
    patch.mk             shared build rules: all check dump gen apply clean
    hooks.S              HOOK_TAIL / HOOK_FULL trampoline macros
    hooks.h              HOOK_DECL and the documented frame sizes
    types.h              u8..s32 with size asserts, absolute-address accessors
    med9_stock.h         GENERATED from re/symbols.csv by
                         tools/gen_stock_header.py -- do not edit
  examples/hello_patch/  the template: copy this directory for a new patch
  ff_counter/            Flash 1, the no-op counter patch (issue #27)
```

## A new patch

1. `cp -r patches/examples/hello_patch patches/<name>` and empty out `src/`.
2. `Makefile`: `NAME := <name>` and `include ../common/patch.mk`.
3. `patch.json`: `name`, `base_sha256`, `ram_status`, and the `build` section
   (`flash`, `ram`, `ram_size`, `blob`, `sym`, `hooks`). Leave `changes` empty —
   it is generated.
4. Write `src/*.c` against `types.h` and `med9_stock.h`; one `HOOK_TAIL` or
   `HOOK_FULL` per hook in `src/*.S`. Need another stock address? Add its
   `re/symbols.csv` name to `WANTED` in `tools/gen_stock_header.py` and
   regenerate — never a literal in patch code.
5. `make check && make dump`, read the disassembly, paste it into `README.md`.
6. `make gen && make apply`, then `python3 -m unittest discover -s tests`.
7. `test/`: an emulator test in `tests/`, a bench procedure with the expected
   log lines written **before** the flash, and a `tolerance.json` for
   `tools/logcmp.py`.

## Rules that the tools enforce, so you do not have to remember them

* `changes` is generated by `tools/patch_gen.py`; hand-editing it is pointless
  because `make gen` and the test suite both overwrite and compare it.
* `tools/patch_apply.py` refuses to write anything if the base image is wrong,
  an `old` is not there, a change lands in the boot block, the on-chip flash or
  the stock calibration (without `"calibration_edit": true`), the
  identification block moves, a checksum fails, or `bindiff` sees one
  unexpected byte.
* `make check` fails on any reference to r2 or r13, on a small-data section, on
  a stale `med9_stock.h`, and if the blob is not exactly the size the linker
  says — which is how an orphan section gets caught.
* `patch.ld` fails the link if `.data` is not empty, if `.bss` outgrows
  `ram_size`, or if the code leaves 0x150000-0x1AFFFF.
* A patch whose `ram_status` is not `"verified"` applies with a loud
  do-not-flash warning. `ff_counter` is in that state until issue #23 lands.
